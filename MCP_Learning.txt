1 Timer/Counter
① 寄存器TMOD
0-1位：设置工作模式  00是13位，01是16位  10是8为自动重装  11是T0分裂成两个8位
2位：0是Timer    1是Counter
3位：外部引脚是否控制定时器启动 (使用 P3.x 控制定时器启动) 	GATE0 = 1 时，只有 P3.2 为高电平，TR0=1 才有效 (否则即便开启了TR0 =1当没有外部信号时候Timer也不工作)
4-7位: 是T1/C1


| 功能类型    | 使用 TMOD 配置 | 时钟来源                          | 用途                 |
| ------- | ---------- | ----------------------------- | ------------------ |
| **定时器** | `C/T = 0`  | 内部时钟                          | 控制时间延迟、定时中断等       |
| **计数器** | `C/T = 1`  | **外部脉冲输入**（P3.4/T0 或 P3.5/T1） | 计算事件次数（如按钮点击、外部脉冲） |

“计数器”就是一个可以统计外部信号脉冲次数的硬件模块。每接收到一个 P3.4 引脚的负脉冲信号，TH0:TL0 加 1直到溢出为止



② 寄存器TCON
| 位号 | 位名      | 全称                            | 作用说明                                                                                                                    | 使用场景               				  |
| -- | ------- | --------------------            | -------------------------------------------- | -------------------------------------------- |
| 7  | **TF1** | Timer1 Overflow Flag   | **定时器1溢出标志位**，当 T1 计满后该位自动置 1。<br>中断方式下会自动清零     | 判断 T1 是否溢出（仅查询模式用） |
| 6  | **TR1** | Timer1 Run Control     | **控制 T1 的启动或停止**：1=启动，0=停止                                                             | 开启/停止 T1           			  |
| 5  | **TF0** | Timer0 Overflow Flag   | **定时器0溢出标志位**，T0 溢出时置 1。<br>中断方式会自动清 0                           | 判断 T0 是否溢出         			  |
| 4  | **TR0** | Timer0 Run Control     | **控制 T0 的启动或停止**：1=启动，0=停止                                                             | 开启/停止 T0           			  |
| 3  | **IE1** | External Int1 Flag           | **外部中断1 请求标志**，INT1 触发时置 1。<br>中断服务后自动清零                     | 不建议查询，自动处理         		  |
| 2  | **IT1** | External Int1 Type         | **INT1 触发方式选择**：0=低电平触发，1=下降沿触发                                            | 推荐设为 1（边沿触发）       		  |
| 1  | **IE0** | External Int0 Flag          | **外部中断0 请求标志**，INT0 触发时置 1。<br>中断服务后自动清零                      | 不建议查询，自动处理         		  |
| 0  | **IT0** | External Int0 Type         | **INT0 触发方式选择**：0=低电平触发，1=下降沿触发                                            | 推荐设为 1（边沿触发）       		  |

IEx当触发中断时自动=1，中断函数结束后自动=0。没有开启 ET0，INT0 触发仍然会让 IE0=1必须手动清0
TFx触发中断=1，在中断函数里自动清零， 你没有开启 ET0，只是让定时器计数 你在主程序中 手动轮询判断：TF0 == 1 ⚠️ 此时 TF0 不会自动清零！你必须手动清
***总结：如果没用进入中断函数，则IEx和TFx需要手动清零


THx和TLx是定时器的高8位和低8位，每次时间到了(溢出)后要手动设置THx和TLx才可以开始下一次定时工作否则会从0开始计时

计数周期时间 = 12 / 11.0592MHz ≈ 1.085 μs
定时时间（秒） = (65536 - 初值) × 1.085μs
初值 = 65536 - (延时时间 / 1.085μs)


定时器的一个数字就是一个机器周期 定时器的溢出与TFx=0或1没关系，TFx只是一个标记主要用于逻辑查询和中断

内容							是否需要你 TF1=0 清零
串口波特率发生器（方式1）		❌ 不需要 ✅
定时器中断模式				❌ 中断自动清
查询 TF1 做定时逻辑				✅ 必须手动清零

3 串口通信

	定义：数据一位一位依次发送。

	典型协议：
		UART（异步串口）：TX/RX线。
		SPI：主从结构，SCLK、MISO、MOSI、SS。
		I²C：双线（SCL、SDA）。

	优点：布线简单、成本低、适合远距离通信。
	缺点：带宽较低（单线传输）。


数据通信方式
│
├── 并行通信（Parallel Communication）
│   └── 并行接口（如并口打印机、旧LCD并口）
│
└── 串行通信（Serial Communication）
    	├── 通信方式
    	│   ├── 同步串行通信（如 SPI,...）
    	│   └── 异步串行通信（如 UART,...）
    	│
    	├── 串行通信协议（逻辑层）
    	│   ├── UART（就是我们通常说的“串口通信”）
    	│   ├── SPI
    	│   ├── I²C
    	│   └── CAN、LIN（车载）
    	│
    	└── 串行接口（硬件物理层）
        	├── RS-232（UART常用的物理层）
        	├── USB（本质是高速串行）
        	├── SATA、PCIe   一些蓝牙模块


| 协议层     | 传输方式   | 接口名称         | 举例说明             |
| ------- 	  | ------ | ------------ | ---------------- |
| UART 协议 | 串行（异步） | RS-232、TTL串口 | 单片机串口通信、电脑 COM 口 |
| SPI 协议    | 串行（同步） | SPI 接口       | 连接传感器、Flash 芯片   |
| USB 协议  | 串行（高速） | USB 接口       | 键盘、U盘等外设         |
| I²C 协议    | 串行（同步） | I²C 接口       | OLED 屏幕、温湿度传感器   |


| 通信方式                 		  | 说明               				 | 举例         |
| -------------------- 		  | ---------------                                | ---------- |
| **单工（Simplex）**          | 数据只能单向流动                           | 键盘 → 电脑    |
| **半双工（Half Duplex）** | 双向通信，但同一时刻只能一方发    | 对讲机、UART   |
| **全双工（Full Duplex）**  | 双向通信，同时发送接收                  | 电话、SPI（双线） |



① (1) UART协议

| 特性        	| 描述                           					|
| --------- 		| --------------------------- 				|
| **异步通信**    | 不需要时钟线，只需 TX 和 RX 两根线       		|
| **双线全双工** | 发送和接收可同时进行（靠时序区分）           	|
| **字节为单位** | 每次发送 1 字节（8 位数据 + 起始 + 停止位）   |
| **波特率匹配** | 通信双方必须使用相同波特率（如 9600）          |


| 引脚名        | 说明       | 连接说明         |
| ---------- | -------- | ------------ |
| TXD (P3.1) | 发送引脚（输出） | 接到电脑串口接收（RX） |
| RXD (P3.0) | 接收引脚（输入） | 接到电脑串口发送（TX） |


| 位   | 内容     | 示例                  |
| --- | ------ | ------------------- |
| 起始位 | 1 位低电平 | 开始传输（0）             |
| 数据位 | 8 位数据  | 如 `0100_0001` → 'A' |
| 停止位 | 1 位高电平 | 传输结束（1）             |
总共 10 位，每一位必须按固定速率发送，这就是我们要设置波特率的原因

| 常见波特率  | 意义            |
| ------ | ------------- |
| 9600   | 每秒传输 9600 bit |
| 115200 | 更高速           |

步骤         		控制线状态变化
--------     	---------------------
1. 选通道     	设置 ADD A/B/C 三线
2. 锁地址     	ALE = 1 → 0 （上升沿触发地址锁存）
3. 启动       	START = 1 → 0（上升沿触发启动转换）
4. 等待完成   	观察 EOC 变为 高电平 → 转换完成  只读型
5. 输出数据   	OE = 1，读取 D0~D7 并口输出的数值  (电平触发)
6. 关闭输出   	OE = 0，准备下一次转换

// 2. 锁地址
ALE = 1; delay_us(2); ALE = 0;

// 3. 启动转换
START = 1; delay_us(2); START = 0;

// 4. 等待结束
while(EOC == 0);

// 5. 读取数据
OE = 1;
adc_value = P2;
OE = 0;

	方法2：用单片机的 定时器中断，在中断服务函数中翻转一个 IO 引脚 → 自动输出稳定方波。
	#include <reg52.h>

sbit CLK = P3^7;  // 输出到 ADC0809 的 CLK 引脚

// Timer0 中断初始化（例：50us 进一次中断 → 输出 10kHz 方波）
void Timer0_Init()
{
    TMOD &= 0xF0;       // 清除 T0 模式位
    TMOD |= 0x01;       // 设置为定时器模式1（16位）
    TH0 = (65536 - 50) >> 8;  // 高8位（假设1us计数一次）
    TL0 = (65536 - 50) & 0xFF;// 低8位
    ET0 = 1;             // 允许T0中断
    EA = 1;              // 允许总中断
    TR0 = 1;             // 启动定时器
}

void Timer0_ISR() interrupt 1
{
    TH0 = (65536 - 50) >> 8;
    TL0 = (65536 - 50) & 0xFF;
    CLK = ~CLK;          // 翻转输出引脚
}

温度范围	-55℃ ~ +125℃
精度	±0.5℃（在 -10~+85℃ 范围内）
分辨率	9~12 位可选（默认 12 位）
响应速度	最快 750ms（12位精度下）
唯一地址	每个 DS18B20 内部带唯一 64位地址
多点测温	可多个传感器并联，仅占一个I/O口




| DS18B20 引脚 | 单片机连接说明                    |
| ----------  | -------------------------- |
| GND        | GND                        |
| DQ          | 任一I/O，如 P3.7 + 上拉电阻（4.7kΩ） |
| VDD        | VCC（5V）或浮空（寄生电源）           |


64 位 ROM 地址结构
| 字节位置    | 内容            | 说明                       |
| ------- | ------------- | ------------------------ |
| \[0]    | Family Code   | 1 字节，固定为 `0x28`（DS18B20） |
| \[1\~6] | Serial Number | 6 字节，唯一识别码               |
| \[7]    | CRC 校验码       | 校验前 7 字节是否正确             |


ROM 指令
指令名			十六进制	说明	用途场景
Read ROM		0x33	读取当前传感器的 64 位唯一地址	单总线下仅连接一个传感器
Match ROM		0x55	精确匹配某个设备地址	多个设备时精确访问
Skip ROM		0xCC	跳过识别步骤，默认对全体广播	常用于只连接一个设备
Search ROM		0xF0	扫描总线上所有设备地址	多设备搜索
Alarm Search		0xEC	查找温度越限报警的设备	报警场景使用
功能指令
Convert T		0x44	启动温度采集（需要等待转换时间）
Read Scratchpad	0xBE	读取温度寄存器（9 字节数据）
Write Scratchpad	0x4E	写入警戒温度（TH/TL）与精度配置
Copy Scratchpad	0x48	将配置数据写入 EEPROM
Recall E²			0xB8	从 EEPROM 恢复配置


1）拉低 DQ → 初始化 ≥ 480μs  主机释放DQ	等待从机响应	从机拉低约 60~240μs
2）发送 0x55 和 发送地址，或 0xCC（跳过ROM识别）
3）发送 0x44（启动测温）
4）等待转换（≥750ms）
5）重新初始化 操作(1)
6）发送 0x55 和 发送地址，或 0xCC（跳过ROM识别）
7）发送 0xBE（读取温度寄存器）
8）读取低/高字节 → 转换为温度值


void DS18B20_Read_Temp_By_ROM(unsigned char rom[8]) {
    DS18B20_Init();
    DS18B20_WriteByte(0x55);      // Match ROM
    for(int i = 0; i < 8; i++)
        DS18B20_WriteByte(rom[i]);  // 发地址

    DS18B20_WriteByte(0x44);      // Start temperature conversion
    Delay_ms(750);

    DS18B20_Init();
    DS18B20_WriteByte(0x55);      // Match again
    for(int i = 0; i < 8; i++)
        DS18B20_WriteByte(rom[i]);

    DS18B20_WriteByte(0xBE);      // Read temperature

    low = DS18B20_ReadByte();
    high = DS18B20_ReadByte();
    ...
}


void Delay_us(unsigned int us) {
    while(us--) _nop_();  // 实际中根据频率调整
}

bit DS18B20_Init(void)
{
    bit presence;
    
    DQ = 1;
    Delay_us(5);

    DQ = 0;             // 拉低复位
    Delay_us(480);      // 保持低电平 ≥480us

    DQ = 1;             // 释放 DQ
    Delay_us(60);       // 等待从机响应

    presence = DQ;      // 若为0表示设备响应

    Delay_us(420);      // 等待总时序恢复

    return !presence;   // 成功返回1
}

void DS18B20_WriteByte(unsigned char dat)
{
    unsigned char i;
    for(i = 0; i < 8; i++) {
        DQ = 0;
        Delay_us(2);

        DQ = dat & 0x01;  // 写最低位
        Delay_us(60);     // 保持写时序

        DQ = 1;
        dat >>= 1;
    }
}

unsigned char DS18B20_ReadByte(void)
{
    unsigned char i, dat = 0;
    for(i = 0; i < 8; i++) {
        DQ = 0;
        Delay_us(2);

        DQ = 1;
        Delay_us(5);       // 给从机拉低时间

        dat >>= 1;
        if(DQ) dat |= 0x80;

        Delay_us(60);
    }
    return dat;
}

float DS18B20_ReadTemp()
{
    unsigned char temp_L, temp_H;
    int temp;
    float real_temp;

    DS18B20_Init();                // 初始化
    DS18B20_WriteByte(0xCC);      // Skip ROM
    DS18B20_WriteByte(0x44);      // Convert T
    Delay_us(75000);              // 转换等待 ≥ 750ms（9位精度）

    DS18B20_Init();
    DS18B20_WriteByte(0xCC);      // Skip ROM
    DS18B20_WriteByte(0xBE);      // Read Scratchpad

    temp_L = DS18B20_ReadByte();  // 读取温度低位
    temp_H = DS18B20_ReadByte();  // 读取温度高位

    temp = (temp_H << 8) | temp_L;
    real_temp = temp * 0.0625;    // 转换为实际温度（浮点）

    return real_temp;
}

SPI

| 引脚名            | 全称                         		| 主机方向  | 作用说明               |
| ---------- 	| -------------------------- 	| ---- 	 | ------------------ |
| **SCK**    	| Serial Clock（串行时钟）       | 输出   	 | 主机产生时钟信号，控制数据传输节奏  |
| **MOSI**   	| Master Out Slave In        	| 输出   	 | 主机发送数据给从机          |
| **MISO**   	| Master In Slave Out        	| 输入   	 | 主机接收从机返回的数据        |
| **CS**（SS） | Chip Select / Slave Select 	| 输出   	 | 主机片选信号，低电平表示选中哪个从机 |


主机一次只能选中一个从机（CSx拉低）
         主机 MCU
     ┌───────────────┐
     │               │
     │   MOSI ────────────▶ 从机1
     │   MISO ◀────────────
     │   SCK  ────────────▶
     │   CS1  ───────────▶ 低电平的从机被选中，其他的为高电平
     │   CS2  ───────────▶ 从机2
     │   ...              ...
     └───────────────┘

| 特性           | 描述                               |
| ------------ | -------------------------------- |
| ⏱ **全双工通信**  | 主机每发送一个 bit 的同时也接收一个 bit（数据同步交换） |
| 🧠 **主机驱动**  | 主机主动发起通信，提供 SCK 时钟               |
| 🔀 **可配置时序** | CPOL/CPHA 配置可调整时钟沿与采样方式          |
| 🔧 **支持多从机** | 每个从机单独接一条 CS（SS）选通信号线            |


每个字节的数据先从最高位发送
SPI 的 “写”和“读”不是分开的动作，而是 边发边收、同频同步进行

4 种 SPI 模式（由 CPOL / CPHA 组合而来）是由从机出厂设的  
主机和从机必须使用相同的 SPI 模式
模式号	CPOL	CPHA	空闲时钟电平	采样时机	说明
模式 0	0	0	低	上升沿采样	⭐默认/常用模式
模式 1	0	1	低	下降沿采样	
模式 2	1	0	高	下降沿采样	
模式 3	1	1	高	上升沿采样	

void SPI_Init() {
    MOSI = 0;
    SCK  = 0;  // 或 1，取决于 CPOL
    CS   = 1;  // 片选默认拉高
}

unsigned char SPI_Transfer(unsigned char data_out)
{
    unsigned char data_in = 0;
	
    for (int i = 0; i < 8; i++) {
	SCK = 0;
        // 在上升沿前准备 MOSI 数据
        MOSI = (data_out & 0x80);   // 发送最高位
        data_out <<= 1;
	SPI_Delay();
        // 产生上升沿（CPHA=0 ⇒ 上升沿采样）
        SCK = 1;
	// 上升沿采样 MISO
        data_in <<= 1;
        if (MISO) data_in |= 0x01;
	SPI_Delay();
        // 产生下降沿，为下一个位做准备
        SCK = 0;
	SPI_Delay();
    }
    return data_in;
}

void SPI_Delay() {
    _nop_();  // 或者简单的循环空转   执行一个空指令，相当于浪费一个机器周期
}

void SPI_WriteByte(unsigned char dat) {
    CS = 0;                     // 片选使能
    SPI_Transfer(dat);          // 发送数据
    CS = 1;                     // 取消片选
}



CPOL=0, CPHA=0，也就是说主机和从机都是在上升沿发生后才能读取对方传输的数据
从机或主机在边沿触发后读取MISO和MOSI的数据，然后再准备下次的数据通常是在SCK=0期间准备
如果在两个上升沿之间MISO或MOSI变化，如果再次采样就是变化后的结果 (因此不希望多次采样)
